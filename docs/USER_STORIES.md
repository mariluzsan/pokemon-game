# Historias de Usuario

## Objetivo
Formalizar las funcionalidades del juego desde la perspectiva del usuario y del sistema.

| ID | Historia | Prioridad |
|---|---|---|
| US-01 | Como jugador, quiero iniciar una partida para comenzar el juego. | Must |
| US-02 | Como sistema, quiero seleccionar un Pokémon para construir una ronda. | Must |
| US-03 | Como jugador, quiero visualizar el personaje oculto para intentar identificarlo. | Must |
| US-04 | Como jugador, quiero disponer de un tiempo limitado para responder. | Must |
| US-05 | Como jugador, quiero enviar mi respuesta para conocer si acerté. | Must |
| US-06 | Como jugador, quiero obtener puntuación según mi desempeño. | Must |
| US-07 | Como jugador, quiero conocer el resultado de cada ronda. | Must |
| US-08 | Como jugador, quiero finalizar la partida al completar las rondas. | Must |
| US-09 | Como jugador, quiero solicitar pistas cuando las necesite. | Must |
| US-10 | Como jugador, quiero recibir pistas generadas con IA sin que revelen la respuesta. | Must |
| US-11 | Como sistema, quiero limitar las pistas por ronda. | Must |
| US-12 | Como sistema, quiero penalizar el uso de pistas. | Must |
| US-13 | Como sistema, quiero impedir que una pista revele el Pokémon. | Must |
| US-14 | Como jugador, quiero recibir una pista alternativa si falla la IA. | Must |
| US-15 | Como sistema, quiero registrar el desempeño del jugador. | Must |
| US-16 | Como sistema, quiero calcular su nivel de desempeño. | Must |
| US-17 | Como sistema, quiero adaptar la dificultad según el desempeño. | Must |
| US-18 | Como sistema, quiero seleccionar Pokémon acordes con la dificultad. | Must |
| US-19 | Como jugador, quiero que mi resultado final quede guardado. | Must |
| US-20 | Como jugador, quiero consultar el ranking. | Must |
| US-21 | Como sistema, quiero ordenar correctamente las puntuaciones. | Must |
| US-22 | Como jugador, quiero visualizar claramente el ranking. | Must |

Los criterios verificables se centralizan en `ACCEPTANCE_CRITERIA.md`.
